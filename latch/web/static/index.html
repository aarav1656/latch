      How the two Nemotron models split the work

      1. 1Read the pull request, its linked issue, and both commits. No model.
      2. 2Lightning maps the repository and triages the issue. nvidia/Nemotron-3_5-Lightning
      3. 3Ultra writes the test from the issue text alone. nvidia/Nemotron-3-Ultra-550b-a55b
      4. 4The harness runs the test on base and head, reverts the fix to check the test fails again, and sets the verdict. No model decides it.

      Each receipt lists the calls it actually made. Anything a receipt did not record shows as not recorded.

      What happens when the gate stays shut

      If the proof test still fails on an agent's fix, a Nemotron coding agent rewrites the code and the harness runs everything again. The model never decides: the gate opens only when the frozen proof test is green and the repository's own suite stays green.
