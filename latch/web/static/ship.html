Run Latch on every pull request.

Latch posts the receipt as a comment. The same engine that powers this site ships as a command line tool and a composite GitHub Action. Both are in this repository. Nothing here runs on your code until you add it to your workflow.

1. Command line

Prove a pull request, then render the receipt as a comment. The comment command is a dry run unless you pass --post and set GITHUB_TOKEN.

Shell

export NEBIUS_API_KEY=...     # read from the environment only, never a flag
latch prove --repo . --base BASE_SHA --head HEAD_SHA --issue-file issue.md --receipt receipt.json
latch comment receipt.json      # dry run: prints the comment, posts nothing
latch comment receipt.json --post --repo OWNER/REPO --pr N   # needs GITHUB_TOKEN

2. GitHub Action

The composite Action lives in .github/actions/latch. The workflow below is the example we ship (latch/loop/github/latch.yml), minus its comments. It needs a repository secret named NEBIUS_API_KEY. Pull requests from forks get no secrets, so Latch reports an error there and fails closed.

.github/workflows/latch.yml

name: latch
on:
  pull_request:
    types: [opened, synchronize, reopened, edited]

permissions:
  contents: read
  pull-requests: write   # post or update the single Latch comment

concurrency:
  group: latch-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  latch:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0          # Latch needs the base and head commits
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install the project's own test dependencies
        run: python -m pip install -e . pytest
      - uses: aarav1656/latch/.github/actions/latch@main   # or ./.github/actions/latch inside the Latch repo
        with:
          mode: prove                      # "loop" lets Nemotron repair a shut gate and re-judge
          test-command: python -m pytest -q
          nebius-api-key: ${{ secrets.NEBIUS_API_KEY }}
          # post-comment: "false"          # only write the receipt and the job summary
          # fail-on-shut: "false"          # report, but do not fail the check

Inputs: mode (prove or loop), test-command, base, head, issue, max-iterations, nebius-api-key, github-token, post-comment, fail-on-shut, python-version. Outputs: verdict and receipt. See .github/actions/latch/action.yml.

3. What the comment says

Verdict
PROVEN or NOT PROVEN, with the reason when it is not proven.
Evidence
The proof test name, what happened on base and head, the revert check, and the triage verdict.
Models
A collapsed table of the model calls the receipt recorded, and the generated test source.
Update
One comment per pull request, updated in place on each push.

Scope

  • Python repositories with pytest. Other languages are not supported.
  • The pull request description must link the issue it fixes, for example Fixes #123.
  • Every run makes model calls with your own key and costs credit. Latch does not run on a pull request unless the workflow does.
  • The Action and the comment renderer are tested against fixtures. This site has not posted a comment to a real pull request.

Latch proves that a patch changes behaviour the issue asked for. It does not review code quality.
